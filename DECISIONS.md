# Decisions

Settled architectural and product decisions. Do not reopen without new
information that directly invalidates a stated reason.

| ID | Decision | Chosen | Rejected | Reason | Date | Status |
|---|---|---|---|---|---|---|
| D-001 | Acoustic solver | k-Wave (k-wave-python), 3D k-space pseudospectral | Own FDTD solver; Isaac Sim; ray/BEM acoustics | At 20–24 kHz λ≈14–17 mm ≈ finger width, so diffraction dominates and a full-wave solver is required. Isaac Sim has no acoustic wave solver. Ray methods ignore diffraction. Own solver = months validating PML/stability/dispersion that k-Wave already publishes. GPU smoke test already passed on Kaggle T4. | 2026-10-11 | active |
| D-002 | What is simulated | One band-limited pulse per pose; store impulse response; synthesize chirp response offline | Simulate the full chirp in k-Wave | Channel is LTI. IR window is ~1.5–3 ms (set by range window) vs ≥10 ms chirp. Chirp params change without re-simulating. | 2026-10-11 | active |
| D-003 | Dimensionality | 3D | 2D slices | Ring wraps a finger; finger geometry and inter-finger shadowing cannot be represented in 2D. | 2026-10-11 | active |
| D-004 | Tissue/solid model | Uniform c = c_air everywhere; solids get ρ = 1000 kg/m³, density Gaussian-smoothed per D-036 | Physical tissue c ≈ 1540 m/s | CFL time step scales with c_max: c = 1540 costs ~4.5× more steps. Air–solid reflection is ≈0.999 either way; transmission into tissue is irrelevant to the echo. | 2026-10-11 | active |
| D-005 | Motion within a frame | Quasi-static: one static pose per frame | Moving geometry inside a sim run | ~1 m/s finger motion moves ≤2 mm (≤1 cell) across the IR window. Doppler ignored for v1. | 2026-10-11 | active |
| D-006 | Device abstraction | `DeviceConfig` object; one pipeline for every device | Separate phone and ring pipelines | Validation on the phone only transfers to the ring if the code path is identical. | 2026-10-11 | active |
| D-007 | Pre-ring validation device | iPhone 17 Pro | Laptop | Phone is a rigid box with dimensioned port locations (Apple Accessory Design Guidelines); repeatable clamp rig. Laptop hinge/lid/keyboard geometry cannot be modeled accurately. | 2026-10-11 | active |
| D-008 | Processing code | One package `ringsim.proc` (numpy/scipy only) used by sim and real | Separate sim-side and hardware-side processing | Any processing mismatch contaminates the measured sim-to-real gap. | 2026-10-11 | active |
| D-009 | What is stored | Raw IRs + pose params + labels; profiles computed on load | Store processed profiles | Changing processing must never force re-simulation. | 2026-10-11 | active |
| D-010 | Storage format | HDF5, one shard per sim job | zarr; npz | Kaggle output is downloaded as files; one self-describing file per job is the simplest unit; h5py available everywhere. | 2026-10-11 | active |
| D-011 | Pose source | Real MANO motion sequences (GRAB / InterHand2.6M) + pose-space random walks, ~70/30 | Random poses only | Differential profiles depend on realistic finger dynamics; random walks fill coverage gaps. | 2026-10-11 | active |
| D-012 | Label format | Ring-a-Pose 20-joint wrist-relative format | MANO-native joint set | Baseline comparability. MANO 21 joints − wrist = 20. Ordering and frame: D-025. | 2026-10-11 | active |
| D-013 | v1 domain randomization | MANO betas, ring rotation about finger, ring shift along bone (D-026), speed of sound (temperature, applied at read time per D-037), sensor noise | Also transducer response, extra reflectors, sleeve | Smallest set covering the largest expected gaps; rest deferred to v2 after real data shows what matters. | 2026-10-11 | active |
| D-014 | Capture app location and build | In this repo; XcodeGen + GitHub Actions macOS runner → unsigned IPA → sideload | Separate repo; local Xcode | No Mac available; user already has a working Actions-build + sideload flow; validation phases depend on the app. | 2026-10-11 | active |
| D-015 | Phone validation band | 18–22 kHz | 20–24 kHz (ring band) | iOS records at 48 kHz; anti-alias roll-off starts near 22 kHz. The physics check does not require the ring's band. | 2026-10-11 | active |
| D-016 | Compute | Kaggle T4 script kernels via `kaggle` CLI; local CPU for small grids | Kaggle P100; Colab | k-Wave CUDA binary needs compute capability ≥7.5; P100 is 6.0. T4 path already proven. | 2026-10-11 | active |
| D-017 | Grid spacing | Chosen by Phase 3 convergence study against measured real noise floor | Fix a value now | 1 mm costs 8× 2 mm; only data can justify the cost. | 2026-10-11 | active |
| D-018 | Phone rig | Phone in a clamp, free air, ≥40 cm from other surfaces | Phone lying on a table | Table is a large reflector that would have to be modeled. | 2026-10-11 | active |
| D-019 | tx/rx alignment | Align on direct speaker→mic path peak | Assume fixed device latency | iOS I/O latency varies by route and buffer size; the direct path is always present in sim and real. | 2026-10-11 | active |
| D-020 | Non-goals of this repo | Sim + validation only | Include model training, calibration routine, firmware | Separate suites; keeps this one finishable. | 2026-10-11 | active |
| D-021 | Real-world far reflectors | Crop all profiles (sim and real) to the configured range window | Model room/body reflectors in v1 | Sim domain has absorbing boundaries; anything past the window is not simulated, so it must not be compared. | 2026-10-11 | active |
| D-022 | Phone chirp timing | 600 samples @ 48 kHz = 12.5 ms, continuous (chirp fills the period), 80 frames/s | Short chirp + silence; other lengths | Mirrors Ring-a-Pose's 600-sample continuous FMCW (§3.3) so the phone validates the same processing path; band stays 18–22 kHz (D-015). | 2026-10-11 | active |
| D-023 | Phone transducer pair | Bottom speaker (4 holes, x_draw 15.40–22.16) + bottom mic 2 (x_draw 24.42) | Earpiece + front mic; bottom speaker + bottom mic 1 | Only pair fully dimensioned in Apple's drawing: front mic position inside the receiver slot is not given. Mic 2 sits 2.26 mm from the nearest speaker hole and 5.6 mm from the speaker-hole centroid, close to Ring-a-Pose's 5.4 mm spacing. Which physical mic iOS's `bottom` data source uses is confirmed by the Protocol A hole-cover test (Q-005). | 2026-10-11 | active |
| D-024 | Ring inner diameter | Derived per frame from the MANO finger cross-section at the ring plane, clearance 0 | Fixed diameter from a ring size | Ring-a-Pose sized each ring to the wearer with a yarn knot (§3.2); a fixed diameter would intersect or float off MANO fingers across betas. | 2026-10-11 | active |
| D-025 | Label convention | MediaPipe keypoints 1–20 (wrist 0 subtracted), mapped from MANO via MANO_TO_MP20, in a canonical frame: x = wrist→index MCP, z = palm normal; `hand_scale_m` = wrist→little MCP stored separately | MANO joint order; pre-scaled labels | Ring-a-Pose trains on MediaPipe labels, palm-plane aligned and size-normalized by wrist→little MCP (§3.6.1). Storing metres + scale lets the training suite reproduce their normalization exactly. | 2026-10-11 | active |
| D-026 | Ring position randomization | Shift ring ±10 mm along the bone in sim | Only post-hoc bin shifts on profiles | Ring-a-Pose's ±3-bin vertical shift (±10.3 mm) models ring position variation and was their most effective augmentation (§3.6.4, §8.2.6). Sim can model the physical cause directly. | 2026-10-11 | active |
| D-027 | Capture-app delivery | CI unsigned IPA (Debug archive, `CODE_SIGN_IDENTITY=""`) → signed with free Apple ID via Sideloadly/AltStore on Windows | Signing in CI; TestFlight | Same pipeline already proven on lapse-app (its D-023). Free provisioning cannot be automated; paid program not needed for an internal tool. | 2026-10-11 | active |
| D-028 | Capture-app debugging | In-app ring-buffer debug log + Log tab | os_log console; third-party SDK | Sideloaded builds have no debugger/console without a Mac; same reasoning as lapse-app D-024. | 2026-10-11 | active |
| D-029 | Ring signal parameters | 50 kHz, 20–24 kHz FMCW, 600 samples (12 ms) continuous, 54 range bins from the direct path, 5th-order Butterworth band-pass | Own parameter choices | Copied from Ring-a-Pose §3.3–3.4 so the baseline replication and sim data share one signal definition. | 2026-10-11 | active |
| D-030 | Human-facing project record | Obsidian vault `03-competitions/isef-ring-pose/`: hand-written overview, append-only log, project decisions; spec docs mirrored by `scripts/obsidian_sync.py` | Hand-copying specs into the vault; vault as spec source of truth | User wants the vault as work log, overview, and documentation. Hand copies drift from the repo within a week; a generated mirror cannot. | 2026-10-11 | active |
| D-031 | Wrist boundary of the MANO mesh | Attach a 0.40 m straight forearm extrusion from the wrist loop; domain bbox excludes it so it runs off the grid into the PML | Close the wrist with a flat cap (`fill_holes`); model nothing past the wrist | A flat cap is a strong reflector ~10 cm from a middle-finger ring, inside the 18.5 cm window, that no real hand has; the model would learn it. Running the arm into the PML absorbs it with no end echo. | 2026-10-12 | active |
| D-032 | Phone tx output | Stereo buffer with the chirp on one channel only, the channel that Protocol A step 0 shows drives only the bottom speaker; orientation locked to portrait | Play the mono WAV (both speakers) | iPhone speaker route plays stereo through bottom speaker and earpiece; two sources 150 mm apart break the one-source sim. | 2026-10-12 | active |
| D-033 | Convergence criterion | Differential-profile error e(dx) < 0.25 × separation between different finger motions, on random and adducted-finger poses, with a 0.75 mm check of the 1.0 mm reference | Static-profile error < 0.5 × real static noise floor | The model learns from motion. Static noise on a clamped phone is tiny, so the old rule would force a grid far too expensive for Kaggle without saying anything about what the model needs. Adducted poses catch fingers fusing at coarse dx. | 2026-10-12 | active |
| D-034 | Shipping code to Kaggle | Wheel `0.0.0+g<hash>` uploaded to private dataset `ringsim-code`, installed from `/kaggle/input` | `pip install git+https://github.com/...@hash`; GitHub token in the kernel | git install fails for a private repo; a token in a kernel is a credential to manage. The wheel works either way and still pins the exact commit. | 2026-10-12 | active |
| D-035 | Version pins | Python 3.13 (`==3.13.*`), k-wave-python 0.6.2 | Older Python minor; unpinned k-wave-python | Measured on Kaggle "GPU T4 x2" on 2026-10-14: Python 3.13.15, k-wave-python 0.6.2, CUDA binary ran on T4. 0.6.2 deprecates `kspaceFirstOrder3D`; pinning keeps the API stable. | 2026-10-14 | active |
| D-036 | Density interface | Gaussian-smooth ρ with σ = 0.5 cell after voxelization | Sharp ρ jump; sharp jump at lower CFL; σ = 1.0 cell; lower solid ρ (30–300) | Smoke run on CPU and T4 (identical): sharp ρ 1.2→1000 goes NaN at CFL 0.3; at CFL 0.05–0.15 it is stable but echo/direct = 0.088 vs rigid prediction 0.141 (−38%) and CFL-converged, so a spatial error. σ = 0.5: 0.134 (−5%) at 64³ and 0.069 vs 0.073 (−6%) at 124³, stable at CFL 0.3. σ = 1.0: −15%. Lower ρ: −17% to −40%. | 2026-10-14 | active |
| D-037 | Where temperature enters | Simulate every frame at c = 343 m/s; apply temperature at read time as H(f) → α·H(f/α), α = c(T)/343; sim window sized for the coldest supported air (10 °C) | Simulate each sequence at its own c (old DATASET.md design) | With uniform c (D-004) and no absorption, the wave equation gives h_{αc}(t) = α²·h_c(αt) exactly. Checked 2026-10-14 on CPU: scaled vs direct sims at 337/349 m/s differ by 0.03%/0.10%, versus 5.4–5.6% with no correction. One shard then serves every temperature, temperature randomization costs no simulation, and shards drop per-sequence c, dt and decimation. | 2026-10-14 | active |
