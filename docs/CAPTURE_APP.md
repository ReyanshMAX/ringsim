# CAPTURE_APP.md — iOS recorder app ("RingCapture") and its CI build

## Overview

Minimal SwiftUI app that loops a tx WAV through a chosen iPhone speaker while
recording raw audio from a chosen built-in mic, with all OS audio processing off.
Saves float32 WAV + JSON metadata, exported through the Files app. Built on GitHub
Actions (no Mac, D-014) as an unsigned IPA, then signed with a free Apple ID and
sideloaded from Windows — the same pipeline already working for lapse-app (D-027).

## Non-goals

- No on-device processing, plots, or profiles. Analysis happens in Python.
- No network, accounts, cloud sync, or analytics.
- No chirp synthesis on device: tx comes only from WAVs exported by
  `ringsim export-tx`, so the transmitted signal is byte-identical to the sim's.
- No background recording.

## Audio configuration (must match exactly)

```swift
// AudioRig.swift
enum Route: String, Codable { case earpiece, bottomSpeaker }
enum MicSource: String, Codable { case front, bottom }

func configure(route: Route, mic: MicSource) throws {
    let s = AVAudioSession.sharedInstance()
    let opts: AVAudioSession.CategoryOptions = (route == .bottomSpeaker) ? [.defaultToSpeaker] : []
    try s.setCategory(.playAndRecord, mode: .measurement, options: opts)   // no AGC/NS/EC
    try s.setPreferredSampleRate(48_000)
    try s.setPreferredIOBufferDuration(0.005)
    try s.setActive(true)
    guard s.sampleRate == 48_000 else { throw RigError.sampleRate(s.sampleRate) }  // reject, never resample
    let builtIn = s.availableInputs?.first { $0.portType == .builtInMic }
    try s.setPreferredInput(builtIn)
    let want: AVAudioSession.Orientation = (mic == .front) ? .front : .bottom
    if let ds = builtIn?.dataSources?.first(where: { $0.orientation == want }) {
        if ds.supportedPolarPatterns?.contains(.omnidirectional) == true {
            try ds.setPreferredPolarPattern(.omnidirectional)
        }
        try builtIn?.setPreferredDataSource(ds)
    } else { throw RigError.noDataSource(mic) }
}
```

Engine: `AVAudioEngine`; `inputNode.isVoiceProcessingEnabled` must be `false` (assert).

Single-speaker output (D-032). On the built-in speaker route iPhones play stereo through
both the bottom speaker and the earpiece, so a mono WAV would chirp from two places
150 mm apart and the one-source sim would not match. The app therefore never plays the
mono file directly:

```swift

    // zeros in the other
```

`AVAudioPlayerNode` is connected to the main mixer with an explicit 2-channel format and
schedules the stereo buffer with `.loops`. Interface orientation is locked to portrait so
iOS's left/right → speaker mapping cannot change mid-session. Log
`AVAudioSession.currentRoute.outputs` (port type, channel count, channel names) at every
session start. The channel that drives the bottom speaker is found by Protocol A step 0
and stored as the default in `UserDefaults` (`txChannel`). Input tap on
`inputNode` (bus 0, native format, mono channel 0) writes into an `AVAudioFile`
(float32, 48 kHz, mono). Start the tap first, then the player, so the first tx frame
is captured (alignment uses the direct path, D-019).

Take rules (D-073):
- 48 kHz everywhere or no take: the session rate, the input node's native format, the
  output node's format and the tx WAV's file rate must all be 48000 (the tx WAV must also
  be mono); otherwise the take is refused, never resampled.
- Built-in only: after configuration every route output must be `builtInSpeaker` or
  `builtInReceiver` and every input `builtInMic`; otherwise the take is refused.
- Length: the take holds exactly duration × 48000 frames; the tap chunk that crosses it
  is cut. `duration_s` in the JSON = frames written / 48000.
- Abort: a route change mid-take (the route's port types + UIDs differ from those at take
  start; a notification with the same route does not count) or an audio-session
  interruption aborts the take, deletes its partial files and logs it.

## Bundle

XcodeGen adds `Resources` as a group, so Xcode copies `Resources/tx/*.wav` flat into the
app bundle root; the app lists the tx files as every `.wav` at the bundle root.

## Metadata JSON (per take)

```json
{
  "schema_version": 1,
  "take": "plate_110mm_t2",
  "started_utc": "2026-10-20T01:02:03Z",
  "duration_s": 10.0,
  "tx_file": "phone_tx.wav",
  "tx_channel": "left",
  "tx_sha256": "<hex>",
  "route": "bottomSpeaker",
  "mic_source": "bottom",
  "sample_rate": 48000,
  "io_buffer_s": 0.005,
  "input_latency_s": 0.0,
  "output_latency_s": 0.0,
  "data_source_name": "<AVAudioSessionDataSourceDescription.dataSourceName>",
  "polar_pattern": "omnidirectional",
  "ios_version": "<UIDevice.current.systemVersion>",
  "device_model": "<utsname.machine>",
  "label": "free text from UI"
}
```
Latency fields are recorded from `AVAudioSession` for diagnostics only; processing
does not use them (D-019). `device_model` from `utsname`; do not hardcode.

Field rules (D-073). Every key is always written; no other keys.
- `take` = the saved file stem after `_2`/`_3` dedup; `label` = the raw UI text.
- `tx_sha256` = SHA-256 of the tx WAV file bytes, lowercase hex.
- `duration_s` = frames written / 48000 (see "Take rules").
- `input_latency_s`, `output_latency_s`, `io_buffer_s` are read at Record start.
- `data_source_name` / `polar_pattern` = the route input's selected data source and its
  selected polar pattern (lowercased, e.g. `omnidirectional`); JSON `null` when unavailable.

## Debug log (D-028)

Sideloaded builds have no debugger or console. `DebugLog` keeps the last 500 lines
(timestamp + message) in memory and mirrors them to `Documents/debug.log`. Log every
session config step, chosen data source name, actual sample rate, route change
notifications (`AVAudioSession.routeChangeNotification`), interruptions, engine errors,
and file write results. A "Log" tab shows it with a Copy button.

## UI

Default route/mic: `bottomSpeaker` + `bottom` (D-023), tx channel from `UserDefaults`. Single screen (includes a tx-channel picker: left / right / both): route picker, mic picker, tx file picker (the bundle's tx WAVs, see "Bundle"), take label
text field, duration stepper (1–60 s, 1 s steps), Record button (disabled while recording),
list of saved takes with delete. Files saved to the app's Documents dir as
`<label>.wav` + `<label>.json`; duplicate labels get `_2`, `_3`.

- tx channel (D-073): no default. Until `UserDefaults` holds `txChannel` the picker shows "not
  set" and Record is disabled; picking a channel writes it to `UserDefaults`.
- tx file: starts unset ("none"); Record is disabled until one is picked (D-074).
- Label: Record is disabled while the label is empty or has a character outside
  `[A-Za-z0-9_.-]`.

## CI build

```yaml
# .github/workflows/ios.yml
name: ios
on: {push: {paths: ["capture-app/**", ".github/workflows/ios.yml"]}, workflow_dispatch: {}}
jobs:
  build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - run: brew install xcodegen
      - run: cd capture-app && xcodegen generate
      - name: Archive unsigned          # same recipe as lapse-app's `ipa` job
        run: |
          cd capture-app && xcodebuild -project RingCapture.xcodeproj -scheme RingCapture \
            -configuration Debug -destination 'generic/platform=iOS' \
            -archivePath build/RingCapture.xcarchive \
            CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY="" archive
      - name: Package .ipa
        run: |
          cd capture-app && mkdir -p Payload
          cp -R build/RingCapture.xcarchive/Products/Applications/RingCapture.app Payload/
          zip -qry RingCapture.ipa Payload
      - uses: actions/upload-artifact@v4
        with: {name: RingCapture-unsigned-ipa, path: capture-app/RingCapture.ipa}
```

Install (developer, Windows): `gh run download -n RingCapture-unsigned-ipa`, then sign and
install with the free Apple ID in Sideloadly/AltStore, as for lapse-app. CI never signs.

## Acceptance (Phase 2)

- CI produces `RingCapture.ipa`; installs and launches on the iPhone 17 Pro.
- A 10 s take with the bottom speaker / bottom mic config produces a WAV whose length is
  10 s × 48000 ± 1 buffer and a JSON matching the schema above.
- `ringsim real` on that WAV shows a direct-path peak at bin 0 and a stable profile
  across frames with no target present.
- With `mode: .measurement` removed (manual test build), the profile visibly changes;
  confirms processing is actually being bypassed in the real build. Revert after.

## Notes

- If the bottom speaker is too quiet in 18–22 kHz (Protocol A pass condition), that is a
  finding to record, not a bug: do not add gain stages.
- Free Apple ID limits: 3 sideloaded apps per device and a 7-day signature expiry.
  lapse-app already uses 2 bundle IDs (app + Live Activity extension); RingCapture is the
  3rd. Re-sign weekly during capture periods. If the slot is needed, uninstall lapse-app
  temporarily rather than adding extensions here.
- `[device]` acceptance items are done by the developer and reported back; CI green does
  not satisfy them.
- Never enable Bluetooth or AirPods routes; reject any route that is not built-in.
